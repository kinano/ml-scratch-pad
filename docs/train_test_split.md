# train_test_split

`train_test_split` from scikit-learn splits a dataset into a training set and a test set. The model learns from the training set and is evaluated on the test set — data it has never seen. This separation is essential because a model evaluated on its own training data has no way to prove it learned generalizable patterns rather than just memorizing the data.

A good split balances two competing needs: the training set must be large enough for the model to learn, and the test set must be large enough to give a statistically reliable evaluation. Common defaults are 80/20 or 70/30. For small datasets (under ~1000 samples), a single split may not satisfy both needs — cross-validation is preferred instead, rotating through multiple splits so every sample contributes to both training and evaluation. For large datasets, even a small test percentage yields enough samples, and a three-way train/validation/test split is common: the validation set is used during development to tune the model, while the test set is reserved for a single final evaluation.

Shuffling randomly reorders the data before splitting. This is on by default (`shuffle=True`) because real datasets are rarely in random order — they may be sorted by class, collected in batches, or otherwise structured in ways that would make a naive split unrepresentative. The one exception is time series data, where order must be preserved so future data cannot leak into the training set (`shuffle=False`).

`random_state` pins the random number generator to a fixed seed, producing the same shuffle — and therefore the same split — on every run. Without it, each run produces a different split, making results irreproducible and comparisons across runs unreliable. This is the ML equivalent of documenting your experimental protocol in science: a prerequisite for reproducibility.

Stratification ensures the train and test sets preserve the same class proportions as the original dataset. Without it, random chance can skew the distribution — especially with imbalanced classes or small datasets — producing a test set that doesn't reflect the real population. Passing `stratify=y` tells scikit-learn to split each class separately before combining. Beyond class labels, the concept extends to grouped stratification (keeping related samples like a patient's scans together), multi-label stratification (balancing across multiple attributes simultaneously), and time-based stratification for temporal data.
